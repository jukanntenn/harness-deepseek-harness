# RFC: 修复第三批消费方接入摩擦

状态：已实施

[English](2026-10-04-third-adopter-friction-batch.md) | 中文

## 问题

第二个实际接入的仓库——progress——顺利走完 plan 与 apply，但暴露出第三批摩擦，同样来自实际观察而非假设。四个缺陷让工具链在接入过程中自相矛盾；五处文档缺口让操作手册落后机制一步。

- **向导把一切探测失败都读成凭据缺失。** `resolve_lifecycle_actor` 用 `gh api user` 探测——一次真实网络调用——但任何非零退出都折叠成 "gh is not authenticated"，与几秒前基于 `gh auth status` 通过的 preflight 直接矛盾；瞬时网络故障重跑即绿，而 gh 缺席时浮出的是裸 `FileNotFoundError` 回溯。
- **已完成的配对无法链接尚未落地的对侧。** 批量翻译落地期间，中文侧链接 `other.zh.md` 会让跨链接门禁红（目标缺失），也会让自己这对的结构签名红（未解析链接退化为裸形态，而英文侧解析为配对锚点）；改链 `other.md` 则让 locale 检查红——它从不回退。没有任何拼写能同时通过两门，于是批次中途的单对提交不可能绿——两个相互独立的翻译 agent 都撞上并读了门禁源码才弄明白。
- **apply 用模板为消费方内容盖章。** 既存真实 `docs/development.md` 时，apply 跳过英文侧写入（还把消费方内容误标为「已安装的占位模板」），照旧在旁边写通用中文模板，并把该配对记录为已确认一致——而 record 的语义是「已复核」——verify 随即报出这对 adoption 从未真正写过的配对缺切换行与五连结构分歧。
- **verify 每次只揭开一个字段的一处分歧。** `structure_diff` 在每个字段首个错位下标后 break，README 译者修一处链接、重跑、再见下一处；更糟的是 record 之后任何编辑都会命中哈希不匹配的提前 return，把全部结构发现遮到重新 record 之后。
- **手册的阶段顺序与依赖相反。** 阶段 1 让你跑 `plan`／`apply`，其 `--project-number` 必填，而创建 Project 看板是阶段 2 的条目——首次接入者必须先偷跑阶段 2 才能开始阶段 1。
- **零门禁的 CI 不可见。** 组过滤 drift 检查只扫描既存的 `prek run --group` 行；直接跑命令的 CI——接入方的实际形态——扫描结果干净，而六个门禁全部只在本地，apply 的输出与手册都不提接线。
- **wrap 迁移成本未定价。** 被接入的 scope 覆盖消费方全部存量语料且不可缩减；一个接入方遇到 84 处 wrap 红点、重排了 83 段，这个成本 ADOPT.md 从未标价。
- **全角标点吞掉裸 URL。** GFM 字面 autolink 只裁剪 ASCII 尾随标点、引用式定义什么都不裁剪，`详见 https://example.com/a，后续` 会把逗号及其后正文一并吞入目标——GitHub 渲染与配对签名同样如此；翻译规则从未警告。
- **中文优先文档没有翻转程序。** 契约允许任一语言先行创作，但英文侧路径上的存量中文文档被静默当作「待翻译的英文文档」；接入方的 agent 只能自行发明搬移动作。

## 决策

**D1——先分类，再诊断。** 一个分类器同时服务 `resolve_lifecycle_actor`、`resolve_account_type` 与 preflight 的 gh 检查：二进制缺席（捕获的 `FileNotFoundError`，与 transport 的缺键哨兵同形）报 "gh is not runnable on PATH"；被拒凭据（gh 自己的 `gh auth login`／HTTP 401／bad-credentials 措辞）保留登录修复指引；其余退出码报出命令、状态与 stderr 首行，作为可重跑的探测失败——绝不指控凭据。不做自动重试：全旗标运行保持离线，hermetic transport 保持确定性。

**D2——未落地配对穿透解析到英文锚点。** 中文侧链接 `X.zh.md`，该文件缺失而 `X.md` 是活跃语料源时，解析穿透到英文源：结构签名两侧都读配对锚点，locale 检查接受自己期望的拼写，generated-region 归一化同步，跨链接门禁放行「`.zh.md` 缺失而英文兄弟存在」的目标。语料级 "must merge bilingual" 错误原样保留——由未翻译的文档本身而非指向它的链接跟踪批次。英文侧误用 `.zh.md` 拼写保持未解析，不指向任何语料文件的链接保持报错。

**D3——模板对原子化并以证据为键。** 任一模板对侧（architecture、development）存在、而上次 adoption 的 manifest 未将其列为已安装时，apply 两侧都不写、什么都不记录，打印一条「从真实内容翻译并手动 record 归消费方所有」的注记；adopt 自己装过的侧保持今日的跳过并记录行为，配对规模注记把被推迟的配对计为待办。

**D4——分歧输出完整。** `structure_diff` 报出每个字段所有错位下标，`_check_pair` 的哈希不匹配分支不再提前 return：out-of-sync 错误保留，其下的 locale、切换行与结构发现照常打印，一次 verify 携带完整修复清单。插入导致的后续下标噪音是去遮蔽的既定代价。

**D5——手册按依赖顺序行文。** git 外清单成为阶段 1——它创建 plan 与 apply 都需要的看板编号——安装成为阶段 2 并携带该编号；后续阶段无需重新编号。

**D6——verify 持有 CI 接线契约。** plan 与 apply 打印接线注记（CI 里跑 prek，或钉版本安装后逐条运行托管门禁），`hdsh adopt verify` 把「workflow 既不调用 `prek run` 也不调用裸 `hdsh` 命令」的 CI 报为 drift——policy workflow 的 `hdsh-ref:` 输入只命名不调用，不计入。完全没有 workflow 的仓库得到一行提示而非 drift。

**D7——plan 为 wrap 迁移定价。** plan 与 apply 统计存量语料中的硬换行段落数（排除 adoption 自己的计划写入），把计数作为一次预算好的机械重排提交打印；手册的退役小节陈述同一成本。

**D8——翻译规则点名 autolink 陷阱。** 排版新增一条 MUST：裸 URL 或引用式定义之后绝不紧跟全角标点或中文——改用方括号链接、尖括号形式，或留一个半角空格。门禁不变：渲染器同样吞字，它报出的结构分歧是真警告。

**D9——翻转程序写入手册。** 阶段 3 明示：`git mv docs/foo.md docs/foo.zh.md` 让既有内容成为中文侧，再翻译英文 `docs/foo.md`，然后 record。不用内容语言启发式检测此类文档；规模注记已把它们计为待办的英文源。

## 验证

聚焦测试钉住每条路径：被拒凭据仍指出登录修复，而连接错误保留退出码与 stderr 且绝不声称缺凭据，gh 缺席在推导器与 preflight 中同样给出安装指引，空 login 显性失败；已 record 的配对链接未落地对侧时 verify 绿，指向非语料文件的链接保持报错，跨链接门禁放行「有英文兄弟的未落地 `.zh.md`」、拒绝没有兄弟的，归一化把未落地对侧折叠到英文锚点，英文侧的 `.zh.md` 拼写保持裸形态；既存真实或中文的模板对侧不落地对侧、不记录、只打一条注记，而 adopt 装过的侧重跑 apply 仍然 record；多处分歧一次打印，哈希漂移不再遮蔽结构发现；零门禁 CI 是 drift，钉版本 `hdsh` 安装或 `prek run` 不是，`hdsh-ref:` 输入不计入，无 workflow 不是 drift；硬换行的存量语料产出重排注记，已重排的不产出。

## 备选方案

**未落地配对临时回退英文侧（D2）。** 否决：每个 sibling 落地都会迫使所有已落地中文侧翻链接并重新 record——逐对工作流会不停改动已完成的配对。

**瞬时探测自动重试（D1）。** 否决：hermetic transport 与全旗标离线运行是契约；诚实的重跑提示能到达同样结果而不引入非确定性。

**autolink 扫描器裁剪全角标点（D8）。** 否决：扫描器镜像渲染器，GitHub 同样吞字——归一化会让门禁放过渲染出来是坏链的链接。

**按内容检测中文优先文档（D9）。** 否决：CJK 占比启发式是在猜测创作语言；语料计数已经定价了工作，程序写明了动作。

**零门禁 CI 只警告不 drift（D6）。** 否决：不被执行的门禁集正是 harness 要关闭的静默空间；drift 消息自带接线配方。

## 后果

本批换来的：preflight 的结论扛得住 plan 期间的网络抖动；翻译批次逐对落地、每个钩子全程绿，从第一天就写最终形态链接；apply 不再为自己没写过的内容盖章，既存的 architecture／development 文档不再带来要删的模板；一次 verify 携带完整修复清单，编辑中途也含在内；手册按执行顺序行文，在 apply 之前为 wrap 重排与配对语料定价，告诉没有接线的接入方如何接 CI，并给中文优先文档一条成文翻转程序。

本批的代价：ADOPT.md 词数上限上调（英文 740→900、中文 270→300）以容纳重排后的阶段与新程序；完成判据新增「把门禁接进 CI」——全新接入的仓库在此之前保持 verify 红，而此前这个缺口不可见；中文侧链接未落地对侧会通过跨链接门禁，批次中途的提交携带落地前 404 的链接——语料级对侧缺失错误仍是跟踪器；一处段落位移现在会报出该字段全部后续下标，用「首分歧的安静」换完整。
