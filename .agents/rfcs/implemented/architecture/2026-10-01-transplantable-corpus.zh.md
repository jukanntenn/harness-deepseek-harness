# RFC: 让被接入的语料可整体迁移且自包含

Status: implemented

[English](2026-10-01-transplantable-corpus.md) | 中文

## 问题

`hdsh adopt` 通过镜像 hdsh 的活文档组装消费方语料，并把离开安装集的链接机械改写为钉住 ref 的上游 URL——这是 [adopt RFC](../feature/2026-09-17-hdsh-adopt-and-templates.zh.md) 记录的设计。边界由改写器事后划定，而非由关于受众的编辑判断事先划定，于是仓库内部内容漏进消费方领地。当时的实测：九个文件共二十八次出站链接改写，主体是对 hdsh 自家决策记录的引用；被镜像的文档标准里带着 hdsh 的社区文件行与接入手册行；行内代码段里的示例链接被改写成已死的上游 URL；预设 hdsh 项目环境的调用；以及把 hdsh 具体工具链当作消费方事实的技能文本。设计目标恰恰相反：被接入的仓库，其文档体系应当表现得如同 hdsh 不存在，就像一个自包含目录被 move 到任何地方依然可用。

## 决策

被移植语料中的内容特化遵循同一个四分模型，并由一个被执行的门禁看守。

### 特化四分法

| 事实的性质 | 机制 |
|---|---|
| 每个仓库各有一个值 | 模板 + 引导占位符，门禁强制直到填完（[占位符完成 RFC](../../proposed/feature/2026-10-01-guided-placeholder-completion.zh.md)） |
| 存在两个仓库都活的载体 | 把事实单源化到该载体 |
| 事实随部署机械变化 | 移植时机械映射 |
| 消费方不需要该事实 | 从消费方形态中移除 |

区分中间两行的规则：存在双方都活载体的事实单源化到该载体，绝不复制成模板——第二份拷贝什么也买不到、只付出一个同步门禁；每个仓库各有一个值的事实做成占位符，绝不泛化成指针——指针不是值，且被指目标可能尚未填写。

### 实际交付

- **决策记录随引用它的内容一起迁移。** 语料引用四篇 implemented RFC，传递再引两篇，六篇闭包以镜像配对整体迁移——adopt 移植两侧语言文件并在消费方仓库录制配对。它们的源码引用改为命令引用，即单源化载体：`uv run hdsh pairing brief` 在两个仓库都活，而 `src/hdsh/pairing/brief.py` 只在一个仓库活。实测该闭包不再有任何出站目标。
- **`rfcs/README` 删去了三处源码链接。** 同一句里的命令与类别表已经承载同样的事实。
- **`docs/AGENTS.md` 改为模板。** hdsh 特有的清单行——社区文件与接入手册——删除，源码路径泛化；hdsh 保留自己的活文件，这是 `architecture.md` 先例上的有意分叉。消费方预存的 `docs/AGENTS.md` 走 standing-orders 待遇：跳过、登记为待合并项、锚点点名。本条扩展[文档标准 RFC](../process/2026-09-07-adopt-documentation-standard.zh.md)。
- **调用前缀在移植时映射。** `SOURCE_INVOCATION`（``uv run hdsh ``）映射为 `CONSUMER_INVOCATION`（``hdsh ``），作用于全部镜像 Markdown，围栏示例与正文一视同仁——命令是给人复制执行的。作者规则一边一形：源语料只写 uv 形态，门禁拒绝镜像中出现裸反引号调用。对镜像语料中非 hdsh `uv run` 命令的拒绝随占位符完成程序落地——该程序把仍携带 hdsh 开发命令的两个技能转为槽位模板——在那里作为该程序的修正案记录。
- **隐藏目录不是散文源。** 枚举式非源目录表升级为类规则——任何以点开头的路径段都标记机器自有领地、留在语料之外，`.agents/rfcs/` 是显式例外——于是 `.zcode/`、`.claude/` 这类 agent 工具镜像永远不进发现范围，pairing manifest 仍是真正例外的阀门。
- **自包含门禁看守不变量。** 一个 hdsh 侧被执行的测试遍历每个镜像文档，断言移植除调用映射外是恒等变换——出站 prose 链接为零、上游 blob URL 为零——源侧只保留 uv 形态，且每篇被引决策记录随语料同行。闭包之外的新引用在写作时即让该门禁变红，这一步把四分法从纪律变成可核查的契约。

对提案的两处修正案，就地记录：改写器的链接提取保留其链接文法、以 CommonMark 反引号串规则掩蔽行内代码段，而非整体换成 markdown 解析器——可执行的不变量是恒等门禁而非提取器的出身，且对语料中的每个代码段而言掩蔽文法就是那条规则；非 hdsh `uv run` 的作者拒绝与上述占位符程序同批落地，因为正是该程序让语料能够满足这条规则。

## 验证

自包含门禁对可迁移语料全绿：渲染后出站 prose 链接为零、死仓库路径为零。被迁移的决策记录三元组在消费方仓库的配对、RFC 与 links 门禁下无需修改即通过——由 adopt 往返测试钉住，同时断言被移植的 README 携带消费方调用形态且不含上游 blob URL。行内代码示例逐字节原样落地（首批接入方批次的代码段修复，保留）。源语料出现裸反引号调用时，作者断言以文件名失败。拥有隐藏目录双语文档的仓库通过 manifest 的 `roots` 阀门选择加入，而不是被自动发现。

## 备选方案

**保留出站引用作为钉住的参考文献。** 否决：被接入的系统肉眼可见地依赖 hdsh——一次仓库改名会同时打断所有消费方的出站链接，且消费方在重新接入前读到的都是 hdsh 文档的冻结快照。闭合模型不需要引用，因为被引用的一切都随迁。

**把工具链措辞泛化成指针，指向仓库自己的命令清单。** 首个消费方撞上时即否决：指针不是值，清单被跟随时可能还是未填的占位符，而 hdsh 自己的技能文本失去具体命令。这正是确立四分法"每仓库一个值"一行的案例。

**给被引用的决策记录建模板做逐位点改写。** 否决：存在双方都活的载体——命令——时，第二份拷贝什么也买不到，反而付出逐位点同步门禁和决策记录的永久分叉。模板保留给真正每仓库各有一个值的事实。

**用磁盘存在性回退归一化语料外链接。** 否决：配对签名将依赖偶然的文件系统状态，且回退会静默祝福错误 locale 的链接——那正是语料纪律要拒绝的东西。

## 后果

本变更买到的东西：被接入仓库的文档完全在自身之内解析——rationale 链接落在被移植的决策记录上，命令在消费方的安装下可运行，没有任何东西指回 hdsh；恒等门禁让回归成为测试失败而非消费方的意外发现；隐藏目录工具镜像默认不再进入语料；文档标准终于描述接入方的树而不是 hdsh 的树。

本变更的代价：hdsh 活文件与消费方拷贝之间出现永久字节差——恰是调用映射——为每个机械镜像检查增加一个 modulo 维度；hdsh 的共享文档失去内联源码指针，代码地图完全住在语料永不移植的 `architecture.md` 里；四分法仍是纪律而非类型系统——门禁证明它知道的那些不变量（出站链接、调用形态、闭包成员），但无法证明新增事实被分进了正确的行，这个判断仍由评审承担。
