# RFC: 让被接入的语料可整体迁移且自包含

Status: proposed

[English](2026-10-01-transplantable-corpus.md) | 中文

## 问题

`hdsh adopt` 通过镜像 hdsh 的活文档组装消费方语料，并把离开安装集的链接机械改写为钉住 ref 的上游 URL——这是 [adopt RFC](../../implemented/feature/2026-09-17-hdsh-adopt-and-templates.zh.md) 记录的设计。边界由改写器事后划定，而非由关于受众的编辑判断事先划定，于是仓库内部内容漏进消费方领地。在当前语料上的实测：九个文件共二十八次出站链接改写，主体是对 hdsh 自家决策记录的引用；被镜像的文档标准里带着 hdsh 的社区文件行与接入手册行；行内代码段里的示例链接被改写成已死的上游 URL；`uv run hdsh` 调用预设了消费方未必存在的项目环境；技能文本把 hdsh 的具体工具链——pytest、ruff、basedpyright、tests/ 布局——当作消费方的事实来陈述。设计目标恰恰相反：被接入的仓库，其文档体系应当表现得如同 hdsh 不存在，就像一个自包含目录被 move 到任何地方依然可用。

## 提案

被移植语料中的内容特化遵循同一个四分模型，并由一个被执行的门禁看守。

### 特化四分法

| 事实的性质 | 机制 |
|---|---|
| 每个仓库各有一个值 | 模板 + 引导占位符，门禁强制直到填完（[占位符完成 RFC](../feature/2026-10-01-guided-placeholder-completion.zh.md)） |
| 存在两个仓库都活的载体 | 把事实单源化到该载体 |
| 事实随部署机械变化 | adopt 时机械改写 |
| 消费方不需要该事实 | 从消费方形态中移除 |

区分中间两行的规则：存在双方都活载体的事实单源化到该载体，绝不复制成模板——第二份拷贝什么也买不到、只付出一个同步门禁；每个仓库各有一个值的事实做成占位符，绝不泛化成指针——指针不是值，且被指目标可能尚未填写。

### 应用

- **决策记录随引用它的内容一起迁移。** 语料引用了四篇 implemented RFC，传递再引两篇，六篇的闭包——十二个语言文件加六份一致性记录——以完整三元组整体迁移，于是每条 rationale 链接都在消费方仓库内可解析。它们的源码引用改为命令引用，即单源化载体：`uv run hdsh pairing brief` 在两个仓库都活，而 `src/hdsh/pairing/brief.py` 只在一个仓库活。实测该闭包在这批引用转换后不再有任何出站目标。
- **`rfcs/README` 删去三处源码链接。** 同一句里的命令与类别表已经承载同样的事实，链接对两边读者都没有增量。
- **`docs/AGENTS.md` 改为模板。** hdsh 特有的清单行——社区文件与接入手册——删除，`src/hdsh/` 路径泛化；hdsh 保留自己的活文件，这是 `architecture.md` 先例上的有意分叉。本条扩展[文档标准 RFC](../../implemented/process/2026-09-07-adopt-documentation-standard.zh.md)。
- **调用前缀在 adopt 时映射。** `uv run hdsh ` 在镜像内容中统一改为 `hdsh `，围栏示例与正文一视同仁——命令是给人复制执行的，这点与链接示例相反。作者规则一边一形：源语料只写 uv 形态，门禁同时拒绝裸 hdsh 调用与非 hdsh 的 uv 命令。消费方在主机上安装 hdsh，映射后的形态才是他们能运行的形态。
- **隐藏目录不是散文源。** 枚举式非源目录表升级为类规则——任何以点开头的路径段都出语料范围，显式语料前缀例外——于是 `.zcode/`、`.claude/` 这类 agent 工具镜像永远不进发现范围，pairing manifest 仍是真正例外的阀门。
- **改写器的链接提取改用 markdown 解析器。** 配对门禁的解析器本来就懂行内代码段不是链接；改写器弃用裸正则、改用同一套提取，代码段缺陷类整体消失，而不是绕着补丁。
- **自包含门禁看守不变量。** 一个 hdsh 侧被执行的测试断言：对可迁移语料，改写除调用映射外是恒等变换——出站 prose 链接为零、死仓库路径为零、被迁移三元组字节稳定。闭包之外的新引用在写作时即让该门禁变红，这一步把四分法从纪律变成可核查的契约。

## 备选方案

**保留出站引用作为钉住的参考文献。** 否决：被接入的系统肉眼可见地依赖 hdsh——一次仓库改名会同时打断所有消费方的出站链接，且消费方在重新接入前读到的都是 hdsh 文档的冻结快照。闭合模型不需要引用，因为被引用的一切都随迁。

**把工具链措辞泛化成指针，指向仓库自己的命令清单。** 首个消费方撞上时即否决：指针不是值，被指清单在被跟随时可能还是未填的占位符，而 hdsh 自己的技能文本失去具体命令。这正是确立四分法"每仓库一个值"一行的案例。

**给被引用的决策记录建模板做逐位点改写。** 否决：存在双方都活的载体——命令——时，第二份拷贝什么也买不到，反而付出逐位点同步门禁和决策记录的永久分叉。模板保留给真正每仓库各有一个值的事实。

**用磁盘存在性回退归一化语料外链接。** 否决：配对签名将依赖偶然的文件系统状态，且回退会静默祝福错误 locale 的链接——那正是语料纪律要拒绝的东西。

## 验收标准

- 自包含门禁对可迁移语料全绿：渲染后出站 prose 链接为零、死仓库路径为零。
- 被迁移的决策记录三元组在消费方仓库的配对、RFC 与 links 门禁下无需修改即通过。
- 行内代码示例逐字节原样落入消费方仓库。
- 源语料中出现裸 hdsh 调用、非 hdsh 的 uv 命令或闭包之外的引用时，门禁以非零退出并点名违反的规则。
- 拥有隐藏目录双语文档的仓库通过 manifest 的 roots 阀门选择加入，而不是被自动发现。

## 风险

- hdsh 活文件与消费方拷贝之间出现永久字节差——恰是调用映射——为每个机械镜像检查增加一个 modulo 维度；它小、确定，且在"单源加映射"的前提下不可避免。
- hdsh 的共享文档失去内联源码指针；代码地图留在语料永不移植的 `architecture.md` 里，hdsh 维护者多走一跳。
- 四分法是纪律不是类型系统：门禁证明它知道的那些不变量——出站链接、命令形态、闭包成员——但无法证明新增事实被分进了正确的行；这个判断仍由评审承担。
