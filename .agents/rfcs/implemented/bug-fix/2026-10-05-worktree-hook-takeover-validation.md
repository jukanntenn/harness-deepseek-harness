# RFC: Validate the worktree hook takeover instead of trusting prek's install defaults

Status: implemented

English | [中文](2026-10-05-worktree-hook-takeover-validation.zh.md)

## Problem

`uv run hdsh worktree install` takes over `core.hooksPath` and delegated the rest to a bare `prek install --overwrite`, which left three paths where hooks silently stopped running. First, prek installs only the hook types its config declares: without `default_install_hook_types` the bare install writes a `pre-commit` stub alone, and nothing hdsh shipped ever declared the key for a consumer. Second, the takeover abandons whatever active plain hooks the default `.git/hooks` directory holds — a consumer's pre-push coverage gate and commit-msg validation simply stop executing when `core.hooksPath` moves, with no warning at install time and no diagnostic afterward. Third, nothing verified which stubs actually landed. The fourth adopter hit exactly this: their pre-push and commit-msg gates vanished after adoption and were restored by hand. Their report attributed the loss to a prek 0.4.11 bug ignoring `default_install_hook_types` in TOML; a clean-room reproduction of that bug failed — 0.4.10 and 0.4.11 both honor the key — but the attribution does not change the defect: observable correctness of the takeover depended on unverified install-time behavior, which is the silent-gate-loss mode this harness exists to eliminate. See [the local Git workflow RFC](../process/2026-09-07-local-git-workflow.md) for the takeover design being repaired.

## Decision

- The declared hook types are read from the consumer `prek.toml`: a missing key means prek's own default (`pre-commit`), and no `prek.toml` at all means the list is unknown. A malformed or empty declaration fails loud at install time.
- The whole declared list is passed to `prek install` as explicit `--hook-type` flags. The flags replace the config list rather than extend it — proven against prek 0.4.11 — so they must carry every declared type; carrying them makes the install independent of whether the running prek honors the TOML key. An unknown list (a yaml config, no config) stays a bare invocation rather than narrowing anything by guesswork.
- After the install, every declared type must have its shim file in the owned hooks directory or the install fails and the takeover rolls back.
- A fresh takeover — no effective `core.hooksPath` in any scope — first scans the default hooks directory (`git rev-parse --git-path hooks`) for executable non-sample plain hooks and refuses, naming each one and its two resolutions: chain it through `prek.toml` (a hook entry at its stage plus `default_install_hook_types`) or rerun with `HDSH_PREK_ALLOW_ORPHANED_HOOKS=1` to acknowledge it stops running. Shims generated by prek or pre-commit are exempt — reinstalling into the owned directory supersedes them — and an already-owned effective hooks path is not rescanned, so reruns stay idempotent.

## Verification

Unit tests pin the declaration parser (present, defaulted, absent, malformed), the exact flag construction for bare and declared invocations, the shim validation, and the orphan scan (executable bit, `.sample` names, both tool-shim markers, directories, missing directories). The fake-prek end-to-end suite proves the takeover contract against real Git: a dropped declared type fails the install with the hooks path rolled back; an unacknowledged plain hook blocks the takeover and is left untouched; tool shims and a taken-over directory do not block; and a config-less repository installs bare without validation.

## Alternatives considered

**Enumerate every hook type unconditionally.** Rejected: it installs stubs the consumer never declared and — because the flags replace the config list — it would widen installs that prek's config deliberately narrows, the mirror image of the defect being fixed.

**Keep trusting `default_install_hook_types` handling.** Rejected: the first field report arrived precisely because the takeover had no proof and no guard; whether any given prek release honors the TOML key is exactly the kind of external behavior an executed invariant should not depend on.

**Warn instead of refuse on orphaned plain hooks.** Rejected: an install-time warning scrolls past, and the failure it predicts — a gate that silently stops running — is the one this repository classifies as most severe; the refusal carries an explicit acknowledgment escape hatch for the deliberate case.

**Migrate plain hooks into prek.toml automatically.** Rejected: writing hook entries for the consumer guesses at environment, ordering, and stage; chaining a hook is a consumer decision the refusal message directs rather than makes.

## Consequences

What the change bought: every takeover is now proven complete — the declared types have shims or the install rolls back — and a consumer's existing gates can no longer vanish silently behind a moved `core.hooksPath`; the failure modes surface at install time with the remedy named.

What it cost: a consumer with active plain hooks faces one explicit step before the first install (chain or acknowledge), and a repository whose prek config is yaml rather than TOML keeps the bare install without validation until a yaml reader exists — a class the adoption path already blocks, so the adopted corpus is unaffected.
