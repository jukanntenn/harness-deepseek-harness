# RFC: skills 镜像缺失已装技能时 adopt verify 给出警告

Status: implemented

[English](2026-10-07-skills-mirror-detection.md) | 中文

## 问题

第五个接入方的仓库用方向无关的同步工具镜像 `.claude/skills/` ↔ `.agents/skills/`。hdsh 只写 `.agents/skills/`，于是第一次镜像运行把空的对侧读作删除，删掉了全部九个已装 skill——先后两次，每次都靠手工重填。文件一旦被删，manifest 的槽位保留机制无从施救，而 `hdsh adopt verify` 全程沉默：镜像树不属于 hdsh，摘要模型里没有任何东西覆盖它。

## 决策

- verify 识别语料实际见过的镜像布局：当 `.claude/skills/` 存在、而已装技能路径——manifest 的 `files`、`editable`、`slotTemplates` 中位于 `.agents/skills/` 之下的条目——在 `.claude/` 下没有对应物时，verify 打印一条提示，点名数量、一个示例路径与补救：运行镜像工具前先把 `.agents/skills/` 复制到镜像侧。
- 该提示不改变退出码。镜像树归消费方所有，缺失对应物不是 hdsh 文件的漂移；`.agents` 侧技能被删仍由既有摘要检查判为硬漂移，已提交路径用 git 即可恢复。
- 接入手册阶段 3 的警告——随第五批接入摩擦修复落地——陈述同一条顺序规则；本提示让该风险存续期间的每次 verify 都把它摆到台面上。

## 考虑过的替代方案

**镜像不完整时判 verify 失败。** 否决：hdsh 不拥有镜像树，无镜像的仓库必须保持绿色，半配置的镜像是消费方自管的状态——提示让风险可见，而不吞并所有权。

**识别所有已知的 agent 镜像布局。** 否决：`.claude/skills` 是接入方真实撞上的唯一布局；对兄弟 skills 目录的泛化扫描会误伤无关工具。识别集合保持封闭，待真实接入方带来第二种布局再扩展。

**apply 时代写到镜像侧。** 否决：apply 将宣称拥有一个由另一工具双向管理的树；复制是消费方自己的第一次镜像运行，靠顺序警告保安全，而不是背着他代劳。

## 后果

换来的是：曾吞掉两轮重填的布局在每次 verify 上带着补救信息自我宣告，退出码则只对 hdsh 自有的漂移保持诚实。

付出的是：携带一个作为常量的已识别布局名，且在镜像补齐之前每次 verify 都打印提示——这是有意的，因为在那之前删除风险一直存在。

## 验证

verify 测试钉住三种状态：已装技能旁存在空镜像目录时打印提示且绿色退出、完全镜像的树不打印、无镜像目录不打印。`.agents` 侧技能被删仍是摘要检查下的硬漂移，由既有的缺失文件测试钉住。
